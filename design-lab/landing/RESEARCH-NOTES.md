# Research notes for the Swarm launch page

Compiled October 16, 2026 from two research agents (agentic visual language and motion; offer page structure, Whop checkout and disclaimers). These are working rules for the three build directions. `SWARM-BRIEF.md` and `docs/swarm-brand.md` outrank this file.

## Gold rule (resolved)

The brand kit says gold is "the core cell, ONE primary button per view, one highlighted number". So a view may hold the lit core cell, one gold primary button and one gold number at the same time, and nothing else gold. Agents, pulses, traces and console text are never gold. Where the research below says "exactly one gold element per view", read it as this kit rule.

WHOP EMBEDDED CHECKOUT (docs read 2026-10-16)
1. Current method: Whop Elements.
- The old URL https://docs.whop.com/payments/checkout-embed now redirects to https://docs.whop.com/elements/latest/checkout/overview. https://docs.whop.com/manage-your-business/payment-processing/embed-checkout also redirects there.
- Docs cover @whop/elements@1.9.0 and @whop/elements-react@1.9.0. npm shows 1.9.0 published 2026-10-12.
- Guide: https://docs.whop.com/developer/guides/embed-checkout. Quote: 'It needs no server code and no API key on the page: the variant defines the price, so the browser never asserts an amount.'

2. HTML snippet (verbatim from docs):
<script src="https://cdn.whop.com/elements/amber/elements.js" data-whop-elements></script>
<div id="checkout"></div>
<script type="module">
  const checkout = window.WhopElements().checkout.create({
    plan: "plan_xxxxxxxxxxxxx",
    metadata: { order_id: orderId },
    returnUrl: `https://yoursite.com/checkout/return?order=${orderId}`,
    onComplete: (completion) => { ... }
  });
  checkout.create("checkout").mount("#checkout");
</script>
The only data attribute is data-whop-elements. All configuration is passed as JS options.

3. React / Next.js:
- Install: npm install @whop/elements-react @whop/elements
- Usage:
  import { Checkout, CheckoutElement, WhopElements } from "@whop/elements-react";
  import { loadWhop } from "@whop/elements";
  <WhopElements elements={loadWhop()}><Checkout plan="plan_xxx" returnUrl=... onComplete=...><CheckoutElement /></Checkout></WhopElements>
- Requirement (docs table): React '^19'. The site has react 19.2.4 and next 16.2.4, so it qualifies.
- My inference: it must live in a 'use client' component, and loadWhop() should be called once (module scope or useMemo).

4. Plan IDs:
- Docs: 'plan: Existing plan ID, prefixed plan_. ... The plan defines the price; nothing about amounts can be asserted client-side.'
- Plans are now called Variants: 'Variant IDs remain prefixed plan_.' (https://docs.whop.com/api-reference/beta/variants/variant)
- Swarm needs 3 IDs: founding monthly, standard monthly, yearly [DATA NEEDED]. Store them as env vars.

5. Switching plans on the page:
- Docs (checkout overview): 'Every option is set at creation: the element mints a checkout session from these values when it mounts. Changing one later with update() or new React props fails instead of changing the existing order. Mount a new checkout to change what is being purchased.'
- My recommendation: the page owns a radio group. On change in JS, call checkout.destroy(), then whop.checkout.create({ plan: next }) and .create('checkout').mount('#checkout'). In React, use <Checkout key={planId} plan={planId}> to force a remount (inference from the quote).
- Each mount mints a session, so mount only on selection, not on hover.
- When the founding variant sells out, default to Standard.

6. Dark theme and accent:
- Docs (https://docs.whop.com/elements/latest/appearance):
  appearance: { theme: { appearance: 'dark', accentColor: 'blue' }, variables: { '--radius': '8px' }, classes: { ... } }
  Pass it globally to WhopElements({ appearance }) or <WhopElements appearance={...}>, or per handle. Change it live with update({ appearance }).
- accentColor is a named scale only: ruby, blue, red, yellow, green, gray, tomato, crimson, pink, plum, purple, violet, iris, cyan, teal, jade, grass, brown, orange, indigo, sky, mint, amber, lime, lemon, magenta, gold, bronze. grayColor: gray, mauve, slate, sage, olive, sand, auto.
- Docs: 'The color scheme is applied before an element's first paint, so dark pages never flash light.'
- My recommendation: theme { appearance: 'dark', accentColor: 'amber', grayColor: 'sand' }, variables { '--radius': '18px' }, classes { 'whop-CheckoutPayButton': { backgroundColor: '#F5C542', color: '#141416', borderRadius: '18px' } }.
- Why amber: Radix 'gold' is a muted brown, and amber is the nearest to #F5C542 (approximate, from memory).
- Docs: 'The framework checks each declaration, then injects the sanitized result inside the element's frame because page stylesheets cannot reach it.' Test whether backgroundColor and fontFamily survive. If they don't, accept Whop's font inside the frame.

7. Limits and requirements, quoted from the overview and guide:
- quantity: 'Plans that disallow multiples refuse values above 1.'
- metadata: 'Up to 40 string pairs.'
- returnUrl: 'Https-only (http for localhost).' The buyer returns with payment and status (succeeded, failed or canceled) and 'must read status before it treats the visit as a sale'.
- onComplete: fires once per mount, but 'a checkout restored on a later page load fires it again for the same result'. Use it for analytics only, and fulfill from the payment.succeeded webhook.
- items: 'Every item must belong to the same seller and use compatible billing terms.'
- Wallets (https://docs.whop.com/elements/latest/checkout/expressCheckout): 'All three wallets require the page's domain to be a verified payment method domain: first-party whop.com pages are pre-approved, and any other site must register its domain through the Payment Method Domains API before any of these buttons renders there.'
- CSP (https://docs.whop.com/elements/latest/getting-started): frame-src https://cdn.whop.com; script-src https://cdn.whop.com; connect-src https://api.whop.com. Add Plaid sources for ACH bank linking (frame-src and script-src https://cdn.plaid.com, connect-src https://production.plaid.com), plus PayPal, Braintree and Google Pay sources for wallets. contentSecurityPolicy() from @whop/elements returns the full list. The site has no CSP today.
- Sandbox: 'The sandbox environment is not yet generally available.'
- The element shows seller policies plus Whop buyer terms under the pay button (.whop-CheckoutTerms), so Swarm's Terms and Refund policy must be published in Whop [DATA NEEDED].
- attribution accepts utmSource, utmMedium, utmCampaign, utmTerm, utmContent, trackingLinkId, funnelId and source. Pass the YouTube video's UTMs so Jesus sees which video converts.

8. Real 'seats left':
- The variant 'stock' field: 'Units available for purchase. null unless the actor has the plan:basic:read scope on the variant's account.'
- Docs: 'Never put a Whop API key in browser code.' So a live count needs a server route (Next.js route handler with an API key) calling GET /variants/{id}.
- Set stock = 50 on the founding variant in Whop [CONFIRM], so Whop enforces the cap, not just the copy.
- Without a live read, show '50 seats only' and no count.

9. Legacy embed (still loads, no longer documented):
- @whop/checkout 0.7.0 was published 2026-09-11, and https://js.whop.com/static/checkout/loader.js still returns 200. Its README points to the old docs URL, which now redirects to Elements.
- Attribute names, read from the package source (https://unpkg.com/@whop/checkout@0.7.0/): data-whop-checkout-plan-id (required), data-whop-checkout-theme (light, dark or system), data-whop-checkout-theme-accent-color (named or hex), data-whop-checkout-theme-background-color (hex), data-whop-checkout-theme-border-radius, data-whop-checkout-theme-button-text, data-whop-checkout-return-url, data-whop-checkout-hide-price, data-whop-checkout-skip-redirect, data-whop-checkout-prefill-email, data-whop-checkout-promo-code, data-whop-checkout-affiliate-code.
- React: import { WhopCheckoutEmbed } from '@whop/checkout/react'; <WhopCheckoutEmbed planId='plan_X' theme='dark' themeOptions={{ accentColor: '#F5C542', backgroundColor: '#0B0B0D', borderRadius: 18, buttonText: 'Join Swarm' }} returnUrl=... />

### Measurable rules (motion and agent UI)

- Hex geometry: pointy-top cells, centre-to-centre pitch = 1.95 x circumradius R (copied from the mark: 39 / 20). Field strokes 1px #1C1C21; each cell outline is drawn at 0.97R.
- Cell size: R = 34px on desktop (pitch 66.3px), 22px on phone (pitch 42.9px). The official mark image size S = 7.5 x R (255px desktop, 165px phone), centred exactly on the core cell centre.
- Core placement: (0.70W, 0.50H) on desktop and (0.50W, 0.34H) on phone. No text box may intersect the circle of radius 3.5R around the core (119px desktop, 77px phone).
- Field fade: alpha 1.0 out to 25% of maxD (the farthest viewport corner from the core), smoothstep down to a 0.12 floor at maxD. Agents stay inside the visible field.
- Field reveal: ring k starts at 45ms x k and fades in over 300ms.
- Agent counts: Canvas 2D 260 desktop / 160 tablet / 90 phone. 3D 360 / 120. GPGPU flow field 4,096 / 1,024. GPGPU all-pairs boids 1,024 / 256 max. Never more than about 1,500 visible agents in any direction (beyond that it reads as smoke).
- Agent marks: 2x2 CSS px head plus a 6 to 10 sample trail (1px, alpha 0.28 scout, 0.42 committed). Scouts #8E8A80, committed #EEEBE4. Never gold, never round dots without heading, no glow or shadowBlur.
- Agent speeds: scanning 2.2 pitch/s on desktop (2.0 on phone); committed up to 4.84 pitch/s; arrival slowing radius 0.9 pitch; separation radius 0.42 pitch; alignment and cohesion radius 1.1 pitch, weights 1.4 and 0.6 multiplied by consensus(t). 72% of agents commit; 28% stay scouts.
- Timeline (all directions): 0 to 600ms field reveal; 200 to 800ms agents wake; 400 to 2400ms independent scanning; 2400 to 3600ms consensus ramp (smoothstep); 2800 to 4400ms neighbours fade to #55555B; resolve at core charge >= 0.9 or 4400ms, whichever is first; SVG opacity 0 to 1 over 240ms, cubic-bezier(.2,.7,.2,1). Everything settled by 4.64s.
- Sensing pings: 120ms rise, 160ms hold, 520ms fade, peaking at #55555B alpha 0.85. Max 8 concurrent on desktop, 4 on phone, 3 after resolve. None within 2 rings of the core once consensus starts.
- Signal pulses: one hop every 70ms, each lit cell holds 160ms then decays over 400ms. Max 6 concurrent on desktop, 3 on phone. They stop at ring 1 and never light the core.
- Gold: exactly one gold element per view at any frame. Before the handoff the canvas or shader core is only a 1.5px gold outline; the gradient, glow and halo come only from the official SVG. No agent, pulse, trace or console element is ever gold.
- 3D directions end top-down: camera FOV 30deg, final distance d = (H/2) / tan(15deg) = 1.866 x H, so 1 world unit = 1 CSS px at z = 0. Tilt from 52deg to 0deg completes before 3900ms, and the camera never moves while the SVG is visible.
- Performance: script plus draw <= 4ms p95 on desktop and <= 6ms p95 on a mid phone. Measured prototypes: 2.80ms and 1.50ms p95 under software rendering. DPR capped at 2 (1.5 for 3D on phone). At most 2 canvases for 2D directions; at most 3 draw calls for WebGL directions.
- Loading: import three.module.min.js r160 from cdn.jsdelivr.net (166 KB transferred, 671 KB raw), never three.module.js (258 KB transferred). Load after LCP. If WebGL or GPUComputationRenderer.init() fails, fall back to the Canvas 2D version.
- Lifecycle: pause the rAF loop when the hero is offscreen (IntersectionObserver, threshold 0) and when document.hidden. Ambient motion after resolve gets a visible pause control (WCAG 2.2.2, motion over 5s) or stops at 5s.
- Reduced motion (prefers-reduced-motion: reduce): no rAF loop and no CSS transitions. Render one still at t = 4700ms: agent streams frozen in the six lanes, neighbours grey, SVG at full opacity, pings and pulses off. 3D directions show the same flat 2D still.
- No text on canvas or WebGL. Every label, status word and console line is DOM text in the kit fonts (JetBrains Mono 500 labels uppercase +0.32em; Hanken Grotesk 400 sentences).
- Console and log mocks: max 6 visible lines; a new line every 900 to 1600ms with randomized gaps; line enter is 160ms opacity plus a 4px rise; older lines step down to opacities 1.0 / 0.7 / 0.45 / 0.25; spinner advances every 80ms; no character-by-character typing. Footer label 'ILLUSTRATIVE AGENT STATES. NOT LIVE DATA. NOT RESULTS.'
- Decision trace SVG: <= 12 paths, 1px #55555B, pathLength=1 with dashoffset 1 to 0 over 700ms, 120ms stagger, pruned branches to #232328 over 300ms. Plays once at 40% visibility, total <= 1.8s.
- Watch-list mock: asset names are redaction bars (#232328, radius 10px), the state chips are WATCHING, NEW THIS WEEK and REMOVED, one state change every 3.5s with a 200ms crossfade, paused on hover or focus, stopped after 3 changes. No sparklines or prices.
- Any boot or status line uses phase words only (SCANNING, CONSENSUS, SIGNAL) with a 3-segment bar, one segment per phase. No percentages, agent counts or IDs that imply a real system.
- Every factual number on the page carries a mono source or date line within 24px of it.
